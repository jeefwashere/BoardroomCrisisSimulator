## Original audio and reviewed text

1. Users explicitly opt in to recording their own speaking turns. Permission is requested through `getUserMedia`; leaving, phase changes, server authority loss and the deadline stop microphone tracks. A short authenticated snapshot guard supplements normal room polling. The capture uses the browser supported MediaRecorder MIME type.
2. `POST /api/rooms/{room_id}/recordings/begin` takes `command_id`, `phase_id` and `round_id`. Only the active authenticated speaker receives a grant. Repeated or recovered same turn requests return the existing grant.
3. `POST /api/rooms/{room_id}/recordings/{recording_id}` accepts bounded JSON containing `audio_base64` and `mime_type`. Original bytes are immutable. The upload route bounds streaming input before JSON parsing. The limit is 10 MB and accepted container types are WebM, Ogg, MP4 and WAV. Original bytes and attribution metadata are saved before returning success, with directory mode 700 and file mode 600.
4. Original files live in `BOARDROOM_RECORDINGS_DIR`, default `.local/recordings`. UUID filenames are generated by the backend. No user supplied file path is used. Metadata includes room, authenticated member, round, phase, timestamps and SHA256. These files do not implement durable recovery of the game itself.
5. `ffmpeg` is required to decode and validate actual duration before a provider call. The decoded duration must fit elapsed capture time, the granted deadline, the total deadline and an authoritative earlier finish, skip or disconnect. A small recorder tolerance is allowed. Excess data stays available as an explicitly failed original, with no transcription call. Install ffmpeg in the server runtime.
6. `POST /api/rooms/{room_id}/recordings/{recording_id}/review` accepts final owner reviewed text. Other members cannot supply it. A reviewed transcript is immutable. Provider speaker labels never grant identity.
7. `GET /api/rooms/{room_id}/recordings/{recording_id}/audio` requires room membership. `GET /api/rooms/{room_id}/extras` supplies recordings and retained contributions. Final evaluation evidence includes original recording references and their transcript status. Pending media can finish after gameplay freezes; committed decisions, original contributions and seat names remain unchanged.
8. Uploads have a 60 second grace after the granted turn deadline. Accepted originals remain readable at game end. Processing tasks are cancelled and awaited on shutdown, with interrupted metadata retained. Paid processing is never retried automatically.

## Speech configuration and spending

Voice spending remains zero until a known price and explicit cap are provided. No paid calls have been made in this run. The existing narration adapter is reused. Speech recognition additionally uses these backend only settings:

```text
BOARDROOM_STT_ENABLED=true
BOARDROOM_VOICE_BUDGET_USD=<authorized positive cap>
BOARDROOM_STT_USD_PER_MINUTE=<verified account price>
BOARDROOM_TTS_LEDGER=<shared private ledger path>
ELEVENLABS_API_KEY=<backend secret>
```

Use the same budget ledger as narration. SQLite reservations happen before each request, including failures; STT conservatively reserves a full minute for an allowed short turn. This is a local spending estimate, not a provider enforced billing cap. Browser tokens are never minted. Startup fails closed for absent prices, cap, key or an unusable ledger. The server accepts browser encoded files and forwards multipart data to `scribe_v2` only after validation.

Official sources: [ElevenLabs transcription](https://elevenlabs.io/docs/api-reference/speech-to-text/convert), [current public pricing](https://elevenlabs.io/pricing/api?price.section=speech_to_text), [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder). Public prices alone do not establish this account's effective rate.

## Final feedback

The factual final report always remains available. Hosted inference uses the existing HTTPS API and keeps both credentials on the backend. Operating system certificate roots are used through the already installed truststore package. No TLS verification is disabled and no new GPU worker is started.

All captured decision, contribution, speaking turn and recording records enter the feedback input. Long text is partitioned without dropping characters to meet the 4000 character prompt limit. Calls are serialized and receive stable request IDs. Output is limited by the service's 256 token cap. Each response must be valid structured JSON and cite only the supplied short evidence identifiers, which the backend maps back to actual records.

The first live multi batch response was truncated. A later structurally valid response inferred missing participants from a partial batch. Both counterexamples are preserved in `docs/evidence`. The accepted implementation therefore generates evidence linked reflection questions, not unverified factual assessments or numerical grades. Factual history is rendered by code. A whole HTTP game with four members completed all three feedback batches through the actual hosted LFM service. Full evaluation quality and an agreed assessment rubric remain separate B12 acceptance work.

Feedback waits for pending uploads, processing and owner transcript review. Missing uploads after grace are explicitly identified. Provider failures show completed and total batches and preserve the factual report. Reflection questions cannot change votes, roles, facts, endings or past contributions. Shutdown cancels and awaits feedback tasks.
